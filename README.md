### 🧭 About me

I build the software that keeps a university running: academics, finance, HR, student affairs. Most of my days are spent inside a large Spring Boot system, figuring out where the domain *actually* draws its lines and making the system easier to see, change, and trust.

I care about **software that fits the business it serves**. That means talking to the people who use it before touching the code, naming things the way they do, and drawing boundaries the code can respect.

Before UCU I went from intern to junior engineer to **CTO at Waape**, where I learned that shipping is a team sport and that customers settle more arguments than code reviews do.

### 🛠️ How I like to build

- **Discover first, code second.** Interviews with real operators beat guessing at requirements.
- **Boundaries matter.** Hexagonal architecture, anti-corruption layers, aggregates that protect their own rules.
- **If you can't see it, you can't fix it.** Observability is a feature, not an afterthought.
- **Teach what you learn.** I write DDD learning material, and I hope to teach software architecture one day.

> 🎯 *Long game:* leading institutional software modernization across East Africa.
